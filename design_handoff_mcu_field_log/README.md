# Handoff: MCU Field Log — visual redesign ("Ink Navy")

## Overview

MCU Field Log is an existing, working single-page app that tracks Marvel films and
series in **narrative order** and hides spoilers until the user asks for them. The app's
logic, data and routing already exist and are **not** changing. This handoff covers a
complete **visual redesign** plus a handful of new UI affordances agreed during the
design process.

The redesign replaces the previous cream-paper "classified dossier" look with a dark
navy system built on one rule:

> **brass = watched · crimson = in progress / spoilers · grey = unwatched**

Nothing else in the UI is coloured. Every status is signalled three ways at once (left
edge, numeral, pill) so a 61-item list can be scanned by colour alone.

## About the design files

The two files in this bundle are **design references created in HTML** — a prototype
showing intended look and behaviour, not production code to paste in.

- `mcu-field-log-v4.css` — this one **is** intended to be used directly. It is plain,
  framework-free CSS written against the app's existing class names and IDs. Dropping it
  in and deleting the old stylesheet should get most of the way there.
- `reference-screens.html` — a static page showing all eight sections side by side with
  representative content. Use it to see intended markup and states. Do **not** ship it;
  the real markup is generated by the app's own JS.

The task is to apply this design inside the app's existing environment and patterns. If
the app is vanilla JS with template strings (as the original screenshots suggest), keep
it that way — no framework migration is wanted or implied.

## Fidelity

**High fidelity.** Colours, typography, spacing, radii, states and transitions are all
final. Recreate them exactly. Where this document and the CSS disagree, the CSS wins.

## Screens

### 1. Main menu

Purpose: orient, resume, choose a phase.

Order top to bottom:

1. **Sticky app bar** (`.app-bar`, 52px, `backdrop-filter: blur(10px)`) — wordmark left
   (`.app-bar__mark`, Special Elite 16px), overall count right (`.app-bar__sub`,
   hidden under 480px).
2. **Masthead** (`.masthead`, centred) — `.app-title` (Special Elite, `clamp(32px,6vw,52px)`,
   uppercase, 0.045em), `.tagline` (mono 11px uppercase, max 52ch), and `.overall`,
   a 200px progress bar + "12 / 112 watched".
3. **Currently watching card** (`.resume-card`) — crimson wash, 4px crimson left edge,
   `.resume-kicker` / `.resume-title` (Special Elite 24px) / `.resume-meta`, and a solid
   crimson `.resume-cta` "Open →". A **series variant** adds `.resume-episode`
   ("Season 1 · on episode 3 of 6") and a crimson progress bar.
4. **"Select a phase"** (`.menu-head`, centred `.section-head` + `.kicker`).
5. **Phase grid** (`#phase-grid`, `repeat(auto-fit, minmax(238px, 1fr))`, 12px gap).
   Each `.phase-card`: `.phase-index` roman numeral watermark absolutely positioned
   top-right, Special Elite 42px, `--fg-strong` at 0.88 opacity, **brass on hover**;
   `.phase-name`; `.phase-sub` (mono uppercase, `min-height: 2.4em` so progress bars
   align across the row); `.progress.progress--sm` pinned to the bottom via `margin-top: auto`.
   Hover lifts 2px. `.is-complete` gets a brass numeral and brass border.
6. **Character Database card** (`.dossier.wide.db-link`) — title, `.db-link__desc`
   (Inter 14px, deliberately *not* mono — it is a sentence, not data), count right.

### 2. Phase list

1. **`.phase-nav`** — `← All phases`, spacer, `← Phase three`, `Phase five →`.
2. **Header panel** (`.dossier.wide`) — kicker "Phase Four", `.section-head`, full-width
   progress + "10 / 61".
3. **`.filter-strip`** — `All`, `Unwatched`, `Watched`, `Series` (`.filter-chip`,
   `.is-active` = brass wash), spacer, `Next unwatched ↓`.
4. **`#case-files`** — `.case-card` rows, 8px gap. Grid `34px 1fr auto 32px`, 4px left
   edge. `.case-num` is Special Elite 19px. `.case-title` Inter 650. `.case-meta` mono
   uppercase ("2021 · series · 9 of 9 eps"). `.case-status` holds a `.stamp` and/or
   `.case-rating`; `.case-dash` (an em dash) when there is no status. `.pin-btn` toggles
   the currently-watching flag.
   States: `.is-watched` (brass edge + brass numeral + dimmed title), `.is-watching`
   (crimson edge, crimson wash, crimson numeral), `.is-unreleased` (grey edge, title at
   weight 500 — **not** opacity-dimmed, so the "Not yet released" badge stays readable).
   Hover slides the row 3px right.
5. **`.list-footer-nav`** — a single right-aligned `Phase five →` pill. Every screen
   reserves 110px bottom padding so this clears the fixed dock.

### 3. Movie detail

Inside `#detail-content`, in order:

1. Title (`.page-title`, 32px) then release line (`.kicker`, "Movie · Released December 17, 2021").
2. **Summary** — `.section-rule` (16px top padding, 1px top border) + kicker + paragraph.
3. **`section.before-watch`** — the orientation panel. Brass 4px left edge, brass-wash
   header bar with `<h3>Before you watch</h3>` and a right-aligned `.bw-safe`
   "No spoilers". **This label is a contract: nothing inside may reveal an event from the
   film.** Body (`.bw-body`) contains, in order:
   - *When this happens* — year/season, what it follows, in-universe gap, runtime, as prose.
   - *What you need to know going in* — prose, state of the world only.
   - *People & things to watch for* — `.chip-row`; plain `.chip` for concepts, `a.chip`
     (brass, `›` affordance) for characters.
   - *Watch these first* — `.bw-prereq` of linked chips.
   - *Helps, but optional* — `.bw-prereq` of `.chip--fact` (mono, borderless).
4. **`section.deep-panel`** — Plot & context. Crimson 4px left edge, full-width crimson
   header button `.deepdive-toggle--head` reading "▶ Plot & context — contains spoilers
   for this film". Collapsed = header only (`aria-expanded="false"` removes its bottom
   border). Expanded reveals `.reveal-panel` with *The full plot*, *Why it matters*,
   *Why this order*.
5. **`section.deep-panel`** — "▶ Spoilers for future films", same treatment via
   `.spoiler-toggle--head`, containing `.detail-list` bullets with `.term` lead-ins and
   `.spoils-tag` markers naming what each item spoils.
6. **`.controls-row`** — `#watch-toggle-btn` (brass solid; `.is-active` inverts to brass
   wash + brass text), `#flag-toggle-btn` (outline; `.is-active` goes solid crimson),
   `.rating` stepper (▼ / value / ▲, brass value, `.is-empty` when unrated).

There is deliberately **no** post-credit-scene count anywhere — it was removed as noise.

### 4. Character database

1. Header panel — count kicker, `.section-head`, lede.
2. `#char-search` — full width, 48px, mono uppercase placeholder, brass focus border.
3. **`.db-controls`** — a `.segmented` sort control: `.seg-label` "Sort" then
   `First appearance` / `A – Z`, active = brass wash. Sorting **reorders one continuous
   grid**; there is no phase grouping (grouping would leak which phase a character
   debuts in).
4. **`section.title-browse`** — crimson-edged, collapsible. Header shows
   "▼ Browse by film or series" left and "⚠ Warning: may spoil who appears in it"
   (`.tb-warn`) right. Body has `.title-picker` → `.title-input` (an `<input list>` bound
   to a `<datalist>`, so the user can **type to filter** 112 titles or click the caret for
   the full list) and a `.hint` line. The caret is drawn with two `linear-gradient`
   background images — note the rule uses `background-color`, not the `background`
   shorthand, which would wipe them.
5. **`.active-filter`** — `.filter-tag` (crimson pill with an ✕ `.clear`) when a title
   filter is on, plus `.result-count`. Unfiltered it shows just the count.
6. **`#character-grid`** — `repeat(auto-fill, minmax(128px, 1fr))`, 12px gap,
   `grid-auto-rows: 1fr` so every tile is the same height.

**`.character-card`** is the most detailed component in the system:

- `.portrait-wrap` clips a square portrait. Real photos are `grayscale(1) contrast(1.06)
  brightness(0.94)` at rest, full colour on hover.
- A **3px brass strip** (`.char-name::before`) sits at the top of the name band at rest —
  this is what stops the grid reading as flat.
- On hover: `.char-name::after` (a full-height brass layer, `transform-origin: top`)
  animates `scaleY(0) → scaleY(1)` over **420ms**, filling the name band to the card's
  bottom edge; the label flips to `--brass-ink` bold; the portrait scales to 1.07; the
  border goes brass. Reverses on mouse-out.
  **Implementation note:** the fill must be `transform: scaleY`, not an animated
  `height` — px→% height transitions do not interpolate and will snap.
- Photo-less characters get `.no-photo` with the initials as its text content, Special
  Elite 34px, plus one of six tints `.no-photo--t1` … `--t6`. **Hash the character name
  to a stable 1–6** so the same person always gets the same tile; otherwise the mosaic
  reshuffles on every render.

### 5. Character file

- **`.char-head`** — `280px 1fr`, `align-items: center`. Left: `.portrait-frame`
  (inset panel, 6px padding) holding a 3:4 portrait or `.no-photo`. Right:
  `.char-name-lg` (Special Elite 30px) and `.char-overview`.
- Deliberately **absent**: watched-progress bar, appearance count, "first seen" — all
  three leak information about titles the user has not reached.
- **`#char-phase-list`** — one row per phase, always all six, so the list itself reveals
  nothing. Exactly **two** states, driven by *the user's* progress and never by whether a
  record exists:
  - `.has-record` — brass 3px left edge. Phase the user has finished; safe to open.
  - `.is-unseen` — crimson 3px edge, crimson heading, and a solid crimson
    `.rec-flag--unseen` "NOT SEEN" chip immediately after the phase name.
  Body copy lives in `.phase-record-body`.

### 6. Series pop-up

`#modal-content.modal--series`, 620px max width, inside `#modal-backdrop` (`.open`
toggles display; `rgba(6,7,10,0.78)` + 4px blur). Structure mirrors the movie detail page:

1. `.modal-head` — title + "Series · 2 seasons · First aired June 9, 2021". 40px right
   padding so `#modal-close` never collides.
2. Overall progress across all seasons ("2 / 12 watched").
3. Summary.
4. `section.before-watch` — same contract as movies, with *People & things to watch for*
   inside it.
5. Two `section.deep-panel` spoiler panels.
6. **Seasons** — `.season-block` per season, collapsed by default. `.season-header`
   shows the season name, `.season-meta` count, and a `.season-mark` "Mark all" pill.
7. **Controls last**, below the seasons, matching movies: Mark series as watched /
   Flag as watching / one series rating.

**`.episode-row`** is a grid `34px 28px 1fr auto`: `.ep-check`, `.ep-num`, `.ep-title`,
`.ep-go` (`›`). `.ep-check` is a 24px `role="checkbox"` — 2px `--fg-faint` border and a
faint fill at rest, brass border + 55%-alpha tick preview on hover, solid brass with a
dark tick when `aria-checked="true"`. Watched rows also gain a brass left edge.

### 7. Episode page

`← Loki` back button plus `← Previous` / `Next episode →` (`.nav-btn.is-disabled` at the
ends of a season). Then episode title (`.page-title` 30px), a kicker
"Loki · Season 1, episode 1 · 51 min", Summary, a `section.before-watch` with
*Where we left off* and *People & things to watch for*, a crimson Plot & context panel,
and `.controls-row` with Mark as watched / Flag as watching. **No per-episode rating** —
rating lives on the series only.

### 8. Now-watching dock

`#now-watching-dock`, `position: fixed` bottom-right, 46px pill, crimson 3px left edge,
`.dock-label` + `.dock-chip`. **Present on every screen.** Full-width above the bottom
edge under 480px. `.now-watching-dock` exists as a class mirror of the ID if a second
instance is ever needed.

## Interactions & behaviour

| Trigger | Result |
|---|---|
| Hover a `.case-card` | background → `--surface-hi`, `translateX(3px)`, 140ms |
| Hover a `.phase-card` | background → `--surface-hi`, `translateY(-2px)`, numeral → brass |
| Hover a `.character-card` | 420ms brass fill down the name band, portrait → `scale(1.07)`, greyscale → colour, border → brass |
| Click `.pin-btn` | toggle `.is-active` on the button and `.is-watching` on the row; update the dock |
| Click `.ep-check` | toggle `aria-checked`; toggle `.is-watched` on `.episode-row`; update season and series counts |
| Click `.season-mark` | tick every `.ep-check` in that season — **needs `stopPropagation`**, it sits inside the `.season-header` button |
| Click "Mark series as watched" | tick **every** episode checkbox in every season; unmark reverses it |
| Click a `.deepdive-toggle--head` / `.spoiler-toggle--head` | toggle `aria-expanded`; the `::after` glyph and bottom border follow from it |
| Click `.season-header` / `.phase-record-head` | toggle `aria-expanded`; `+` ↔ `–` is CSS-driven |
| Reveal panels | `@keyframes reveal`, 180ms, opacity + 4px rise |
| Modal open | `@keyframes pop`, 160ms |

`aria-expanded` drives every disclosure glyph in CSS. **A button must never sit at
`aria-expanded="true"` with no body element** — the design shows an open affordance with
nothing beneath it.

## State

No new app state beyond what already exists: watched set, currently-watching pointer,
per-title ratings, per-episode watched set, and the UI-local state for filters, sort,
search text, chosen title filter, and which disclosures are open.

Two derived values the design now depends on:

- **Per-phase watched counts** for the phase cards and the character-file record states
  (a phase counts as "seen" when the user has finished it).
- **Series roll-up** — episode ticks drive the season count, the series count, and
  whether "Mark series as watched" reads as active.

## Assets

None. The design ships no images, icons or SVG — every glyph is a text character
(`✓ ✕ ▼ ▲ ▶ › ← → ⚑ ⚠ + –`) and every texture is CSS. Character portraits are the app's
own; the design only specifies how they are cropped and filtered. Fonts come from Google
Fonts (Special Elite, Inter, JetBrains Mono) — self-host if the app must work offline.

Studio poster artwork was considered and **deliberately excluded**.

## Things that were removed on purpose

Do not reinstate these without asking — each was cut for a stated reason.

- The 250px full-height masthead on every screen (cost a phone screenful of space).
- The CLASSIFIED stamp and corner tape (decorative, carried no information).
- Post-credit-scene counts everywhere.
- "File 06" / "Personnel file 001" style case-file labels.
- Character watched-progress, appearance counts, and "first seen" (spoiler leaks).
- A "nothing on file" state on character phase records (leaked whether a record exists).
- Phase grouping in the character grid (leaked debut phases).
- Per-episode ratings.
- Studio poster artwork.
